# 电商用户复购与流失分析（Online Retail II）

## 一、项目背景
某英国在线零售商的 B2B/B2C 混合业务，2009-12 至 2011-12 两年交易记录。业务方关注的核心问题是：
**客户买一次就走的多，复购不够，且不清楚哪些客户正在流失。**
本项目旨在量化复购与留存情况、识别高价值客户群、定位流失信号，并给出可执行的运营召回建议。

## 二、数据说明
- **来源**：UCI Machine Learning Repository — Online Retail II（ID 502）
- **文件**：`data/online-retail-ii.xlsx`（原始，两个工作表）／`data/online_retail_ii.csv`（合并后，含 period 列）
- **规模**：1,067,371 行 × 8 列；时间跨度 2009-12-01 至 2011-12-09
- **客户**：5,942 个有效客户 ID，覆盖 43 个国家

### 字段字典

| 字段 | 含义 | 备注 |
|---|---|---|
| Invoice | 发票号 | 6 位数字；以 `C` 开头表示取消/退货单 |
| StockCode | 商品编码 | 5 位数字；另有 POST / D / M / BANK CHARGES 等特殊码 |
| Description | 商品名称 | 有 4,382 条缺失 |
| Quantity | 数量 | 负数为退货，共 22,950 行 |
| InvoiceDate | 交易时间 | 精确到分钟 |
| Price | 单价（英镑） | 5 行为负数（坏账调整） |
| Customer ID | 客户编号 | **缺失 243,007 行（22.8%）**，多为游客下单 |
| Country | 国家 | 43 个国家/地区，英国占绝大多数 |

### 已知数据质量问题（清洗阶段处理）
1. Customer ID 缺失 22.8% → 无法做用户分析，分析层剔除
2. 负数量 22,950 行 → 退货/取消，需与正常订单区分
3. 异常单价（0 元、负数、极高值）→ 需设阈值过滤
4. Description 缺失 4,382 行 → 可从 StockCode 反查补全
5. Invoice 以 C 开头为取消单 → 单独标记

## 三、核心分析问题
- **Q1 留存**：按月分群（cohort）后，新客户在首次购买后 30/60/90 天的复购率是多少？哪几个月的客户质量最好？
- **Q2 结构**：客户购买次数呈什么分布？RFM 分层后，各层客户对销售额的贡献占比如何（是否符合帕累托 20/80）？高价值客户的共同特征是什么（国家/客单价/品类宽度）？
- **Q3 流失**：以"距最后一次购买超过 N 天"定义流失，流失客户与留存客户在购买间隔、客单价、品类数量上有何差异？运营应在哪个时点介入召回？

## 七、SQL 阶段核心发现（2026-11-23）

| 发现 | 数字 |
|---|---|
| 二八法则（更陡） | Top 10% 客户（588 人）贡献 **64%** 销售额；末 40% 客户合计只贡献 4% |
| 复购率 | **71.3%**（按"≥2 个不同下单日"口径；若按订单数口径会虚高，需在报告里写清口径） |
| 季节性 | 9–11 月为旺季（11 月峰值 £116 万），1–2 月为谷底 |
| RFM 分层 | 重要价值客户 27% 人数 → **70.2% 金额**（平均购买 14.8 次）；流失客户 28% 人数 → 仅 4.1% 金额（平均 455 天未购买、仅 1.3 次） |
| 留存 | 次月留存约 19%（如 2010-03 群：442 → 84 人），第 2 月起回升并稳定在 20–25%——新客大量"买一次就走"，但留下来的会持续回访 |

> ⚠️ 报告写作提醒：复购率必须注明口径（"按客户活跃天数 ≥2 天"），因为一个订单拆多行、同一天多单都会虚高订单口径的复购率。
